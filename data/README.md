# Организация данных проекта

Этот каталог содержит исправленную копию исходной мини-выборки и подготовленный датасет для эксперимента YOLOv8.

## 1. Исходная мини-выборка

Предоставленные для задания данные находятся в:

`../test_data/traffic_v5_mini/`

Эта выборка сохраняется без изменений. В исходных данных могут встречаться неполные аннотации или отсутствующие файлы разметки. Отсутствие TXT-файла не означает автоматически, что на изображении нет целевых объектов.

## 2. Исправленная копия

Каталог `raw/traffic_mini_corrected/` содержит проверенную и исправленную копию данных:

```text
raw/traffic_mini_corrected/
├── classes.txt
├── images/
└── labels/
```

- `images/` — изображения;
- `labels/` — аннотации в формате YOLO;
- `classes.txt` — названия классов в порядке их идентификаторов.

Эта копия используется скриптом `src.prepare_dataset` по умолчанию. Она хранится отдельно от предоставленного оригинала, чтобы исправления не изменяли исходную выборку.

После ручного исправления аннотаций необходимо повторно запускать собственную проверку данных и сверять порядок классов и идентификаторы с `classes.txt`.

## 3. Подготовленная выборка

Каталог `processed/` содержит подготовленное разбиение:

```text
processed/
├── dataset.yaml
├── images/
│   ├── train/
│   ├── val/
│   └── test/
└── labels/
    ├── train/
    ├── val/
    └── test/
```

Текущая выборка состоит из 40 изображений, 920 объектов и 11 классов:
- обучающая выборка — 28 изображений;
- валидационная выборка — 6 изображений;
- тестовая выборка — 6 изображений.

Конфигурация `processed/dataset.yaml` задаёт пути к выборкам и соответствие идентификаторов названиям классов. Пути в конфигурации относительны корню подготовленного датасета.

## 4. Повторная подготовка

Команды выполняются из корня проекта.

Посмотреть параметры скрипта:

```bash
./.venv/bin/python -m src.prepare_dataset --help
```

Чтобы создать новую копию подготовленного датасета, не затрагивая текущий:

```bash
./.venv/bin/python -m src.prepare_dataset \
  --output data/processed_rebuilt \
  --seed 42 \
  --report reports/dataset_report_rebuilt.md \
  --manifest reports/manifest_rebuilt.sha256 \
  --visualizations reports/samples/visualizations_rebuilt
```

По умолчанию скрипт использует изображения, аннотации и список классов из `data/raw/traffic_mini_corrected/`. При необходимости входные пути можно передать через `--images`, `--labels` и `--classes`.

Скрипт проверяет входные данные, создаёт разбиение, копирует изображения и аннотации, записывает `dataset.yaml`, формирует отчёт и визуализации, а также рассчитывает SHA-256-контрольные суммы.

Для повторного эксперимента указывайте новый выходной каталог и отдельные пути для отчёта, манифеста и визуализаций, чтобы не затронуть существующие результаты.

## 5. Отчёт, визуализации и контрольные суммы

Связанные материалы находятся в каталоге `reports/`:

- `reports/dataset_report.md` — статистика и состав разбиения;
- `reports/manifest.sha256` — контрольные суммы файлов подготовленного датасета;
- `reports/samples/visualizations/` — изображения с наложенными bounding box.

Для проверки целостности текущей подготовленной выборки выполните из корня проекта:

```bash
shasum -a 256 -c reports/manifest.sha256
```

Сообщение `OK` означает, что файл совпадает с содержимым, для которого был рассчитан соответствующий хеш.

Манифест помогает обнаружить изменение или повреждение файлов, но не восстанавливает их и не доказывает, что аннотации семантически правильны.

## 6. Правила хранения

- Не изменяйте оригинал в `test_data/traffic_v5_mini/`.
- Храните исправления отдельно в `raw/traffic_mini_corrected/`.
- Не смешивайте исходные аннотации с результатами подготовки.
- При изменении изображений, аннотаций или классов повторно запускайте проверку, подготовку и создание манифеста.
- При изменении состава датасета повторно проверяйте статистику и визуализации.
- Соблюдайте правила `.gitignore` и требования задания к объёму данных, включаемых в Git.
